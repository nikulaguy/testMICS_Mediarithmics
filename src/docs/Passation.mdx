# Passation

Cette page s'adresse aux équipes produit et front de mediarithmics. Elle dit **ce qu'est ce dépôt**,
**ce qu'il n'est pas**, et **les façons de s'en servir**.

## Ce que c'est

Un prototype de design system **écrit de zéro**, qui reconstruit le front MICS avec une couche de
composants documentée. Rien n'est extrait du dépôt `mediarithmics-platform` : le code de production
a été **lu** pour comprendre la structure et les comportements, jamais copié.

## Le socle est le vôtre

Le prototype tourne sur **exactement les mêmes versions que votre production**. C'est ce qui
décide si le code se reprend tel quel ou s'il sert seulement de modèle.

Le prototype avait d'abord été monté sur AntD 6 et React 19. Les versions ont été **ramenées sur
les vôtres** précisément pour lever l'objection : un composant copié depuis ce dépôt compile chez
vous sans passe d'adaptation liée aux versions.

Le socle n'était d'ailleurs retenu par rien : aucune API propre à React 19 n'était utilisée — ni
`use()`, ni `forwardRef`, ni les nouveaux hooks — et les seules API AntD un peu récentes
(`popupMatchSelectWidth`, `optionRender`) existent depuis la 5.5 et la 5.11.

Ce qui reste à traiter, au cas par cas : les **imports** (`../ui` ici, chemins Nx chez vous), les
**tokens** — votre produit lit encore deux systèmes en parallèle — et les **graphiques**.

## Les façons de s'en servir

### 1 — Reprendre la couche telle quelle

Vous importez `src/ui.ts` dans le produit. Plus rien ne s'y oppose côté versions : c'est le même
React, le même Ant Design, le même paquet d'icônes.

Reste à faire : réécrire les chemins d'import, et décider ce que devient votre double système de
tokens — c'est le vrai chantier, pas les versions.

### 1 bis — Prendre quelques composants seulement

Le corollaire de l'alignement : vous pouvez copier **un seul fichier**. Les composants *construits*
(`Card`, `Counter`, `Link`, `Overlay`, `TabBar`, `DropdownPanel`, `StatusBadge`, `Icon`…) ne
dépendent presque que du module de thème. Un `Card.tsx` déposé dans votre arborescence compile.

C'est l'option d'entrée la moins risquée : elle se teste sur un composant, en une heure, sans rien
engager.

### 2 — Reprendre le modèle, garder vos composants

Vous gardez vos composants existants et vous reprenez **la méthode** : la surface publique unique,
la règle des trois catégories, le format de page de documentation, la façon de relever une valeur
en production plutôt que de la deviner.

C'est l'option qui coûte le moins et qui donne déjà l'essentiel du gain de passation : un dev
n'ouvre plus une maquette en se demandant quel composant utiliser, il ouvre le Storybook.

### 3 — S'en servir comme banc d'essai

Vous clonez, vous lancez, vous comparez avec votre produit. Le dépôt devient un lieu où trancher des
questions sans toucher au produit : « à quoi ressemble ce composant avec ce token », « ce
comportement, on le veut comme ça ? ».

## Ce que ça change pour la passation

Le point de départ du projet : réduire le temps entre le prototype d'un PM et l'intégration par un
dev, et faire passer le dev **en revue plutôt qu'en interprétation**.

## Ce que le travail a déjà mis au jour

Ce ne sont pas des hypothèses : ce sont des défauts trouvés en reconstruisant, et écrits dans les
pages concernées.

- **Deux systèmes de tokens en parallèle** dans le produit, avec `primary` et `info` **inversés**
  entre le LESS v3 et le thème AntD v5.
- **Douze composants Figma** redessinaient la même surface de carte, à deux valeurs de padding
  différentes. La production en applique une troisième.
- Sur le graphique Stats, **deux séries partagent la même couleur** — « Vector IDs » et
  « User Accounts » sont indistinguables.
- Les libellés d'axes des graphiques sont en **Lucida Grande 11 px**, les défauts de Highcharts, pas
  la police du produit.
- La documentation Figma décrivait des **slots non exposés** : les zones de contenu de la Card
  n'étaient pas injectables.

## Par où commencer

1. **Le Storybook en ligne** — la vue d'ensemble, sans rien installer.
2. **`Design System / Introduction`** — le principe et les trois catégories.
3. **`Design System / Tokens / Fondations`** — les valeurs et les règles qui en découlent.
4. **Un composant au hasard**, par exemple `Card` ou `Tag` — pour voir le format de page.
5. **Le dépôt**, pour lire le code d'un composant et son commentaire : le *pourquoi* est écrit à
   côté du *quoi*.
